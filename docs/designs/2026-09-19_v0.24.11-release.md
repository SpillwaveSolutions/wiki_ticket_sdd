## Delta from the v0.24.10 freeze

The v0.24.10 note already covered the three fixes merged after that tag
(retention archive stability, the #412 marker probe, the merge-gate hardening
with ADR-0011), because its live pair was generated three merges past the
tag. This release ships those three plus the two items below.

### Landed in the architecture

- **The live pair's freshness is a release gate** (`bin/doc_verify.py`,
  `freshness()`). `doc-verify --strict` now reports `STALE` when a live design
  doc's `git_hash` does not descend from the latest tag, or when that tag has
  no freeze record under `docs/designs/` (either the dated note or the
  historical dated pair). Findings are live, so they gate `--strict`; the
  `--staged` pre-commit hook never runs the check, or every commit between a
  tag and its doc PR would fail. Seven releases (v0.24.4 to v0.24.10) had
  shipped with the live pair stamped at v0.24.3 because the regeneration step
  was prose. The release skill's §5 now names the `Agent` call and does not
  finish until the design-docs PR is open. Live design doc §8.11; walkthrough
  §2.21; `tests/test_doc_freshness.py`.
- **`worklog init` writes the CI file for the forge it sees** (#413,
  `plugin/scripts/init.sh`). An Azure DevOps origin (`dev.azure.com`,
  `*.visualstudio.com`) gets `azure-pipelines.yml` with the same two hook-only
  steps as the GitHub Actions template; every other host keeps
  `.github/workflows/worklog.yml`. An existing file is never overwritten,
  `uninstall` removes only a file carrying the `worklog-invariants` marker,
  and `tests/test_plugin.py` (`TestAzurePipelinesTemplate`) keeps the two
  heredocs' commands identical. The tracker adapter and the CI host are
  separate axes. The user guide gains a "CI wiring" section with the
  Actions-to-Pipelines mapping table. Live design doc §27; walkthrough §2.11.
- **Version** `0.24.11` in `bin/worklog`, the four plugin manifests and every
  skill's front matter.

## Open at this freeze

- The merge gate's trust anchor is the status bridge until `WORKLOG_BOT_PAT`
  exists (ADR-0011, Workstream C2, #437).
- Duplicate tickets keep residual causes the probe cannot see: a capped or
  lagging listing, or two syncers that both observe absence. CI-owned sync
  (#438) is the structural answer for the two-syncer case.
- The Azure template is verified in a consuming Azure DevOps project, not in
  this repository's CI; the post-merge bot job stays GitHub-only.
- `trace-check --strict` is still not a CI job; 53 gaps at this tag, most on
  historical work.
