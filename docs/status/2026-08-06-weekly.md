Seven releases shipped in the window — v0.19.0 and v0.19.1 on 1 August,
then v0.20.0, v0.21.0, and v0.22.0 through v0.22.2 over the following five
days.
Sixty-one work items closed. The through-line is not the feature count: it
is that the tooling built to check this repository kept finding defects in
the repository, including in itself.

## What shipped

**Document provenance and citation verification** (17 items, one epic).
Generated documents now carry the commit they were written against, and
`worklog doc-verify` resolves every code citation at *that* commit — telling
a citation that was already wrong when written apart from one that was right
and has since drifted. A hand audit had put the error rate at 12 of 26. The
verifier now checks 400-odd citations on every commit.

**A native Codex plugin**, packaging the same skills as the Claude plugin
plus the lifecycle hooks. The hook scripts are shared verbatim rather than
ported: the two hosts read the same output shape and set the same
environment variable, so only the wrapper differs.

**The information architecture** gained a portable render adapter and a
searchable inventory, and the roadmap, manifest and snapshots all record
which commit their data came from.

## Four defects the tooling found in itself

Worth reading as a group, because they share a shape: **a check that passed
while the answer was wrong.**

| Defect | What the green check was actually measuring |
|---|---|
| The plugin's hooks never fired for anyone who installed it | the manifest was valid JSON — the loader read no events from it |
| `merge-rescue` could return an item to a pre-close state | that no event was *lost*, when state is a fold over *ordered* events |
| Twenty-two tests never ran | the tests that did run, in files whose runner block sat mid-file |
| `doc-verify` accepted a citation pointing at the wrong lines | that the symbol appeared *somewhere* in the cited window |

The hooks defect is the one to dwell on. It shipped for seven releases and
could not be found from inside this repository, because our own sessions
wire the same scripts through settings rather than through the plugin
loader. **The tooling worked for the people building it and not for the
people installing it.** It took an outside report to surface it.

The other three were found by generating the design documents. Twice in
three releases, regenerating prose has turned up a defect nothing else was
looking for — the doc sync is not decoration, it is the only step that reads
the code closely enough to notice.

## Unplanned work

**15 of 61 closed items were unplanned — 24%.** That is high, and it is the
honest number rather than a problem to explain away: eleven of the fifteen
were discovered by the verification work itself, which is what verification
is for. The pattern to watch is that four of them were *follow-ups to
incomplete fixes* — a test that pinned a bug in place, a sweep that covered
one file instead of forty, a changelog section that was never opened. Fixing
the instance and not the class is this quarter's most expensive habit.

## Slippage and attention

Nothing is blocked, nothing is in conflict, and one item is in flight (the
status-report fix that this report is the first consumer of). No item that
was open at the start of the window is still open.

Two things need a decision rather than work:

1. `doc-verify --strict` now reports 48 fabricated citations, all of them in
   **frozen** documents that policy says stay frozen. The pre-commit warning
   therefore never clears, and a warning that always fires is a warning
   nobody reads. Either age frozen documents out of scope, or report only
   findings new against the merge base.
2. **v0.19.0 and v0.22.0 have no frozen design pair.** Both releases skipped
   their doc sync and the moment has passed; manufacturing one now, dated
   today, would be exactly the dishonesty the verifier exists to catch.

## What's next

The version-lockstep step is still a hand edit across thirty-one sites, and
a hand edit is what broke the plugin frontmatter. Making it mechanical is
the highest-value remaining chore. Beyond that: `--strict` is still not
wired into CI, pending the trace-check gap count reaching zero.

## A caveat about this report

The window figures above are the first that are correct. Until today, a
weekly report counted an item as shipped only if a `close` event fell inside
the window — and nightly compaction folds those events away, so **everything
closed more than a day earlier silently vanished from the report.** This
window read as 9 items before the fix and 61 after it. Any weekly report
before this one under-counted, and the earlier ones are frozen, so this note
is the correction.

One limitation remains and is not recoverable the same way: a snapshot's
watermark is the *last* event it folded, so it can restore a close and never
a create. Opened-in-window and any figure derived from it still under-report
after a compaction, which is why the unplanned share above is computed over
closed items.
